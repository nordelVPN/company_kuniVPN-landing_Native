# Экраны, компоненты и функциональные границы

## Структура index.html

Все основные desktop-экраны собраны в одном index с одним header; это секции одного документа, не девять отдельных страниц.

| Порядок / якорь | Референс desktop | Состав |
|---|---|---|
| 1 / #home | 01-home.png | hero, персонаж и брендовый коллаж, крупная CTA с иконками, платформы; сразу под hero отдельная тёмная полоса Stronger Privacy / Reliable Access / Secure Browsing / Multi-Platform |
| 2 / #features | 02-features.png | щит/браузерный art, светлая полоса четырёх преимуществ с рваными краями, сценарии |

После plans — общий footer; login.html использует тот же header/footer. Навигация использует якоря, учитывает sticky header; на служебных страницах возвращает к соответствующим секциям index. language-label не нужен.

## Sign In — отдельная login.html

Слева крупный вертикальный фирменный знак, рваные кремовые края, корона/молния и шахматный декор. Справа заголовок «Welcome Back to KUNI VPN», описание, email, password с показом/скрытием, Keep me signed in, Forgot password?, кнопка Sign In и ссылка Create Account. Все поля с доступными label, ошибками и autocomplete; предусмотрены loading, неверные данные и недоступность сервиса.

Forgot password ведёт на ./forgot-password.html, Create Account — ./create-account.html. Вход после реальной интеграции ведёт в ./account.html; до API не имитировать успешную авторизацию.

## Отдельные служебные страницы

**forgot-password.html:** собственная композиция в стиле kuniVPN (чёрный/оранжевый/кремовый, тот же refined logo и декор), H1, пояснение, email, отправка инструкции, возврат в ./login.html. Состояния: пустое/невалидное поле, loading, нейтральное подтверждение отправки, ошибка/повтор. Для смены пароля по токену — состояние этой же страницы: новый пароль, подтверждение, невалидный/истёкший токен и завершение.

**create-account.html:** H1, email, пароль, подтверждение пароля, требования к паролю по API-контракту, необходимые согласия по предоставленным текстам, Create Account, ссылка на вход. Loading, ошибки полей/сервера, проверка email при необходимости; не придумывать правила сервера.

Для этих страниц нет готового отдельного PNG: разработать новые макеты в существующем стиле и провести отдельную визуальную приёмку.

## Checkout — модальное окно

08-checkout.png задаёт оформление, но не отдельный маршрут. Нажатие выбора любого тарифа в #plans плавно открывает dialog поверх index с выбранным planId. Не переходить на checkout.html.

Компоненты:
- заголовок и закрытие;
- Order Summary: название, срок, полная цена, 5 устройств, условие триала; справочный месячный эквивалент для 3/12 месяцев;
- форма email и выбранного способа оплаты; итог и Continue to payment;
- пояснения о процессе и ошибки.

Перед открытием обновить summary и состояние формы для выбранного плана; повторное открытие другого плана не должно оставлять старую цену. Закрытие кнопкой/Escape/backdrop, удержание фокуса, блокировка фонового скролла и возврат к инициатору. На мобильном — один столбец, ограниченная высота с внутренней прокруткой; клавиатура не закрывает поля и CTA.

При реальной оплате использовать компоненты провайдера/hosted checkout, серверный заказ и подтверждение статуса. Карточные реквизиты не сохранять в localStorage. До интеграции форма имеет явный статус прототипа.

## My Account — отдельная страница account.html

Ориентир 09-account.png. Сначала заголовок My Account и описание, затем боковая навигация и сетка данных.

| Блок | Компоненты / данные | Поведение и состояния |
|---|---|---|
| Навигация | Account, Subscription, Billing, Security, Preferences | активный раздел, keyboard; на мобильном компактная доступная навигация |
| Account Details | avatar, имя, email, дата регистрации, Edit Profile | просмотр/редактирование, сохранение, ошибки, loading |
| Subscription | название плана, статус, срок, 5 устройств, цена, следующее продление только при наличии данных | active/expired/no subscription; Manage Subscription, выбор тарифа |
| Payment Method | бренд и маскированный номер, срок действия, Update | данные только провайдера; нет карты/загрузка/ошибка |
| Billing History | дата, описание, сумма/валюта, статус, документ, View All | список/таблица, empty/error/loading, адаптивный список |
| Security | смена пароля, сессии по доступному API | подтверждение действий, expired session, ошибки |
| Preferences | предоставленные настройки профиля | сохранение и ошибки; не добавлять недоступные функции |
| Help | Need help?, описание, Contact Support | переход в ./index.html#support либо согласованный канал |
| Session | выход | очистка сессии по API, возврат ко входу |

Данные Alex Carter, 59.99/year, 10 устройств и даты на концепте — образцы, не требования. Не копировать их в реальный кабинет. Фактическая подписка приходит с backend; доступ контролируется сервером. На мобильном ориентироваться на mobile/05-account, 06-subscription, 08-payment и 09-help: компактные строки, карточки, большие CTA, удобная иерархия.

## Актуальные тарифы kuniVPN

Источник: данные владельца. Эта таблица имеет приоритет над ценами, сроками и количеством карточек на концептах и над данными Nordel.

| Тариф | Цена за весь срок | Устройства | Возможности / условия |
|---|---|---|---|
| Триал — 1 месяц | 1 | 5 | Один раз для нового пользователя |
| 1 месяц | 7 | 5 | — |
| 3 месяца | 15 | 5 | 5 в месяц |
| 12 месяцев | 55 | 5 | 4.58 в месяц |

Правила реализации:

- Показывать четыре предложения в порядке таблицы на странице тарифов; использовать те же данные в checkout, кабинете и демонстрационных экранах, где отображаются тарифы.
- Цена в основном столбце указана за весь срок. Значения «5 в месяц» и «4.58 в месяц» — справочный эквивалент, а не отдельный ежемесячный платёж; 55 / 12 округляется до 4.58.
- Триал платный: 1 за 1 месяц, доступен один раз новому пользователю. Не называть его бесплатным.
- После триала стандартное предложение на 1 месяц стоит 7. Автоматическое продление, списание и переход на него не заданы.
- Все предложения предусматривают 5 устройств. Правила одновременного подключения не уточнены.
- Прочерк у месячного предложения означает отсутствие дополнительных указанных условий, а не отсутствие функций VPN.
- Валюта, состав функций VPN, автопродление, возвраты и точные правила определения нового пользователя пока не заданы. Не дополнять их по догадке или из концептов.
- Ограничение доступности триала при реальной оплате проверяет backend; скрытие карточки на клиенте не заменяет проверку.

## Мобильная версия

Папка images/consept/mobile — обязательная база детализации. Connect/disconnect, locations, settings — референсы интерфейса приложения; по более позднему ODC-04 product-preview необходимо удалить из лендинга. Эти изображения не требуют добавлять демонстрацию на главную; account/subscription/plans/payment/help — также ориентиры для соответствующих адаптивных веб-компонентов. Не оставлять мобильную реализацию просто уменьшенной desktop-сеткой. Нативное VPN-подключение не возникает от визуального демо.

## Интеграции

Реальные auth, восстановление, регистрация, аккаунт, поддержка и оплата требуют API. Для каждого запроса нужны loading/success/error/empty и поведение при истечении сессии. Тексты о возможностях VPN, страны, скорости и сертификаты не дополнять вымышленными данными.
