# DQA-08 — Сбрасывать весь жизненный цикл checkout при повторном открытии

Статус: Исправлено и проверено: полный reset, generation для async-результатов, инвалидация при close/change, быстрые переоткрытия. Приоритет: P2.

[Исправления и доказательства](../../qa/dqa-fixes.md). Ниже сохранены исходные факты QA и критерии приёмки.

Основание: docs/04 checkout — перед открытием обновить summary и состояние формы; REV-11. Файлы: checkout.js, forms.js.
Два подтверждённых сценария.
1. Отправить trial с валидным email, закрыть во время Loading и открыть yearly. Новый email пуст, но submit остаётся disabled и aria-busy=true; через 300 ms в новом окне появляется результат предыдущей отправки. recheck-edge.json фиксирует yearly и старое сообщение API.
2. После завершённого submit закрыть/открыть другой план; ввод bad до первой новой отправки сразу ставит aria-invalid=true. Внутренний attempted в initForms пережил form.reset. recheck-deep.json.
Тесты используются reduced-motion и локальный прототип, внешние запросы не выполняются. Сценарий старого результата воспроизведён через реальные DOM events requestSubmit/close/reopen; никаких реальных платежей.
Исправление: единый reset формы включает attempted, busy/button/error; асинхронные результаты привязать к конкретной сессии открытия через generation/abort. Закрытие инвалидирует старую операцию. Смена плана внутри открытого диалога должна иметь явно определённое поведение.
Приёмка: закрыть во время loading → открыть любой из 4 планов → чистая активная форма без старого результата; новая валидация не наследует attempted; быстрые повторные открытия, Escape/backdrop, focus return и reduced motion покрыты браузерным regression-тестом.

Доказательства и границы: [повторный аудит](../../qa/design-recheck.md).
