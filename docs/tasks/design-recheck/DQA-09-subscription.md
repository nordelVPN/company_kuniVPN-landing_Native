# DQA-09 — Показывать один выбранный план активной подписки

Статус: исправлено и проверено; sampleSubscription.planId задаёт один план из общей модели. Приоритет: P2.

[Исправления и доказательства](../../qa/dqa-fixes.md). Ниже — исходные факты аудита.

Основание: docs/04 My Account — название фактического плана/срок/цена; REV-12. Файл: pages/account.hbs.
Воспроизведение: account.html → Subscription → Active sample. Показаны одновременно 3 месяца / 15 и 12 месяцев / 55, оба оформлены как активная подписка. Причина: each plans + if monthlyEquivalent вместо одного subscription.planId. Это явно маркированный sample, не утечка реальных данных.
Доказательства: recheck-deep.json содержит полный текст, recheck-edge.json active subscription plan count=2.
Исправление: отдельная модель sample subscription с одним выбранным planId; детали из общей модели тарифов. Переключение разных примеров — отдельный контрол либо отдельные независимые fixtures.
Приёмка: active имеет ровно один план/срок/цену и 5 устройств; expired/empty не содержат активных деталей; реальная интеграция принимает planId backend, без выдуманной даты продления.

Доказательства и границы: [повторный аудит](../../qa/design-recheck.md).
